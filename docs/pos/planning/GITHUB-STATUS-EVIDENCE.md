## Preserved SDK failure diagnosis

The preserved producer observer was inspected directly after the recorded failure.
There are **seven incomplete artifact views among 116 observations**, with **11
artifact errors and zero recorded unresolved module dependency edges**:

- Six Android compile/runtime views have ten ambiguous project-artifact selections.
  The messages state that the consumer did not request `artifactType`; class JAR,
  lint, manifest and other secondary artifacts compete. An untyped view is not a
  reliable observation of the compiler's actual input selection.
- A Desktop detached configuration reports: “Cannot notify listeners of type
  DependencyResolutionListener as these listeners are already being notified.”
  Its trace enters artifact enumeration from the global `afterResolve` observer
  and starts nested dependency resolution.
- The source boundary is [`p2pkit_producer_observer.gradle`, lines 229–238](https://github.com/ukkera/kmp-apps/blob/df01b98/apps/pos/tools/p2pkit_producer_observer.gradle#L229-L238).
  Deferring enumeration addresses reentrancy only; Android still needs explicit,
  correct artifact selection and full required input coverage.

The final binding rejection is correct: required/unclassified artifact-view
failures must not be hidden or relabelled as optional cinterop failures. This is an
observer/validation defect diagnosis, **not a failed compiler result, a tested fix,
a new SDK execution or an accepted RPC build**. Detailed original observations
remain preserved; their source checksums were rechecked during this diagnosis.
