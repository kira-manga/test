# FOOD CASH already-applied and original recovery — v1

Frozen specification, version `1.0.0`, 6 November 2026. Execution status for every
case and variant: **NOT RUN**. This additive design specifies observable behavior;
it does not establish implementation, native capability or workflow acceptance.

The scope is protected source/disclosure and read-only recovery of a genuinely
recorded ordinary `ApplyOriginal` outcome reporting `AlreadyApplied` after its
native original has already been accounted. The
registered `FOOD_CASH_FINANCIAL` version-1 procedures and `sales.food.payment` /1
`ApplyOriginal` body define the remote lane. Fresh cash Start, caller-created
`RecordOriginal`, finalization, refunds, UNKNOWN resolution and central services
are outside this design. A retained original is a prerequisite; an RPC request
cannot manufacture it.

Use [cases.md](cases.md), [fixtures.json](fixtures.json) and
[source-manifest.json](source-manifest.json) together. Cases use business-level
fixture fields, not invented wire DTOs. Public-contract questions `FAA-Q01`–`FAA-Q04`
remain unknown; the corresponding undisclosed details cannot become passing
assertions. Known refusal, authority, identity and conservation requirements remain
fixed even when those questions block a positive variant.

An ordinary `AlreadyApplied` source and a journal returning an earlier `Applied`
terminal result are separate qualifications. That earlier carrier replay cannot
demonstrate an ordinary `AlreadyApplied` source. Lookup/reconnect must retain the existing
operation identity; no replacement operation is prescribed to make that branch
reachable. The exact ordinary-branch setup requires the public clarification in
`FAA-Q02`.

Freeze covers IDs, fixtures, actions, assertions and expected outcomes. Execution
must preserve this version. A correction requires a separately versioned,
requirements-derived rationale; retain v1 and any earlier observed result. Wire the
specified cases to actual production persistence, authority, communication and
native sources at the declared layer. Controlled-port or DATA-only checks do not
qualify actual native storage, admitted RPC, process close/reopen, transport Receipt
ordering, or physical cash. No execution machinery is added by this specification.

Required non-device integration remains separate from emulator/simulator/physical
campaigns and owner acceptance. Minimum OS versions and actual device/adapter facts
must be recorded by execution; they are not defined in these inputs. Unrun, blocked,
failed and central-deferred work never counts as PASS. Local scope uses synthetic
data with central services and optional standby disconnected.
